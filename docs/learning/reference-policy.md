# 학습 근거와 공개 범위

이 프로젝트는 기존 실무에서 얻은 판단과 개인 프로젝트의 실험을 바탕으로 개발 방식을 발전시킨다. 참고 자료를 읽었다는 사실, 직접 작성한 범위, 새로 구현한 기능, 실제 실행·측정 결과를 구분한다.

## 공개 저장소에 남길 것

- 운빨에서 직접 구현한 코드와 필요한 실행 설정 예시.
- 요구사항·설계·API/함수 명세·DTO/모델 검토 기준.
- 기술 선택 이유, 비교한 대안, 운빨에서 직접 재현한 테스트와 실험 결과.
- 합성 데이터로 재현 가능한 절차와 실제 검증 범위·남은 한계.

## 로컬에서만 관리할 것

- 회사 원본 코드·업무 데이터·비공개 문서와 해당 자료의 상세 분석.
- 비공개 저장소·문서의 접근 정보, 개인 장비 경로, 세션·도구 실행 기록.
- `.env`, 비밀번호·토큰·인증서, 애플리케이션 로그와 빌드 산출물.

로컬 참고 인덱스와 상세 검토 문서는 Git에서 제외한다. 공개 저장소를 내려받은 환경에 이 자료가 없더라도 프로젝트 빌드·실행이 가능해야 한다. 자료가 없는 상태에서 기존 구현을 확인했다고 말하지 않는다.

## 적용할 때 남기는 근거

구현 전에 해결할 문제·완료 조건을 정하고, 유지할 방식과 개선할 이유·대안·검증 방법을 연결한다. 성능·안정성 수치는 운빨에서 실제 실행한 환경·입력·명령·결과가 있을 때만 기록한다. 실습·정적 코드 검토·업무 회고를 운영 검증으로 표현하지 않는다.

사전과제에는 기업의 요구사항과 기술·제출 제한을 우선한다. 필요한 원리를 과제에 맞게 구현하고, 허용이 확인되지 않은 회사 코드·설정·데이터는 제출물로 복사하지 않는다.
